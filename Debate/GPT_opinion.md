## **二、V1.0 方法本身：还有四组需要修正的问题**

### **1. M1：Self-FV 的迁移设计还没有与原论文准确对齐**

官方论文的流程是：

1.  使用任务数据和标签扰动样本，筛选显著因果注意力头；
2.  对每个测试 Prompt，提取这些头在当前 Prompt 最后一个 Token 位置的激活；
3.  根据这些激活构造当前 Prompt 的 Self-Function Vector；
4.  将其注入指定层，估计 AU，再用总预测熵减去 AU 得到 EU。

论文采用单次 top-k 干预，并在 Qwen2.5-7B 上验证过；其干预位置设置在 Transformer 深度约三分之一处。

ACL Anthology+2



这里有两个问题。

**第一，不能把离线筛选的因果头集合与离线固定的 Self-FV 向量混为一谈。**

原论文的因果头集合可以通过任务数据离线确定，但 Self-FV 是依赖当前测试 Prompt 的表征。V1.0 应明确区分：

-   离线：标定 RAG 任务的因果头集合 \(S_T^{RAG}\)；
-   在线：依据当前 \(q,\mathcal D\) 的激活构造 \(\hat v_{q,\mathcal D}\)。

如果在线始终使用一个固定的离线向量，就不是原论文定义下的 Self-FV 了。

**第二，当前伪代码的 EU 计算存在明确错误。**

文件中的第 20 行使用了基准上下文的 \(U_{AU,0}\)，直接计算：

\[ U_{EU,i}= \max(0,H(q,\mathcal D_0\cup\{d_i\})-U_{AU,0}) \]

这是不正确的。加入候选证据后，AU 也可能变化，不能沿用旧值。

应当重新计算：

\[ U_{EU}(q,\mathcal D)= \left[ H(p_\theta(\cdot\mid q,\mathcal D)) - U_{AU}(q,\mathcal D) \right]_+ \]

\[ \Delta U_{EU}(q;d_i)= \left[ U_{EU}(q,\mathcal D_0) - U_{EU}(q,\mathcal D_0\cup\{d_i\}) \right]_+ \]

另外，你们利用黄金证据和干扰证据筛选 RAG 因果头，属于新的监督校准程序。它不更新模型参数，但需要标注数据和额外前向计算。因此，更准确的定位是：

**No LLM Parameter Fine-tuning，而不是完全无监督、零校准的 Training-Free。**

### **2. M2：目前最大的算法缺陷，需要改变模块职责**

这里我建议彻底调整 M2 的结构。

V1.0 目前把三个不同问题混在一起：

-   单文档是否值得保留；
-   两篇文档是否互补或冲突；
-   证据应该按照什么顺序送给模型。

这三个问题不能仅靠一个 MST 解决。

例如，假设图中有四个文档：

**最大生成树的节点保留特性**

**A**

0.95

**B**

0.90

**C**

0.85

**D**

-0.20

假设图只有 A-B、B-C、C-D 三条边，且 D-C 权重为负。

**最大生成树仍然必须保留 A、B、C、D 四个节点。**

它会保留三条连接边，因为不选 C-D 就无法让四个节点保持连通。

这就是关键：**最大生成树优化的是边集合，而不是节点集合。**

因此，当前 MST 不能承担“过滤低可靠文档”的职责。即使所有冲突边都被赋予负权，只要它们是连接某个节点的唯一边，标准最大生成树依然会选择它们。

ACL Anthology



还有一个直接的工程问题：如果某个连通分量只有一个孤立文档，那么它的 MST 没有边，伪代码中的：

\[ e^*=\arg\max_{e\in T_m}W(e) \]

将无法执行。

**我建议把 M2 改造成两个明确的子步骤。**

M2-A · 真正的核心创新

**Budgeted Evidence Set Selection**

先决定哪些文档应该保留，而不是先构建一棵树。

\[ \mathcal D^*= \arg\max_{\mathcal S\subseteq\mathcal D_{cand},|\mathcal S|\le K} \begin{aligned} [&\sum_{d_i\in\mathcal S}\tilde R_i +\lambda_1 Coverage(\mathcal S)\\ &+\lambda_2 Complementarity(\mathcal S) -\lambda_3 Redundancy(\mathcal S)\\ &-\lambda_4 Conflict(\mathcal S)] \end{aligned} \]

分别评价节点可靠性、证据覆盖、多跳互补、内容冗余和事实冲突。

M2-B · 证据组织

**Maximum-Spanning-Tree Guided Organization**

对已经选出的证据集合构造关联图，再使用最大生成树提取骨干关系，辅助证据排序和上下文线性化。

MST 负责组织关系，而不负责保证节点可靠性。

这套结构有一个很实际的优势：你们把候选池限制在 15 个文档、最终预算限制在 5 个时，集合选择甚至可以直接精确枚举。

\[ \sum_{k=0}^{5}\binom{15}{k}=4943+1=4944 \]

也就是说，CPU 端只需要评估 4,944 个候选子集，不必为了追求所谓的“高级优化算法”强行引入 GNN 或训练型排序器。

这可能比当前直接把所有职责交给 MST 更合理，也更容易做严谨消融。

另外，M2 的两个权重设计也需要重做：

-   `w_bridge` 目前使用 MinHash 的 Jaccard 相似度。高 Jaccard 表示实体重叠较多，却不一定表示互补；完全重复的文档反而可能得到很高的相似度。应该明确区分“共享实体带来的关联”与“关系链条的互补”。
-   `Conflict` 使用两个文档诱导的首 Token 分布之间的 JS 散度。它实际测量的是**模型预测分布分歧**，不是严格意义上的事实矛盾。不同表达、不同答案粒度、互补证据也可能产生较大 JS 散度。必须通过 claim-level NLI 或受控冲突标注验证它是否能识别真正的事实冲突。

`KG²RAG` 已经使用最大生成树过滤实体关系图中的冗余边，因此 U-GraphRAG 的创新不能是“首次在 RAG 中使用 MST”，而应当落在新的证据节点选择目标和边权机制上。

ACL Anthology+1



此外，\(S_{\rm rel}\) 应归一化到非负、可校准的区间。因为余弦相似度理论上可以为负，而后续 \(R_i\exp(-H_i/\tau)\) 需要正权重。否则文档权重归一化可能失效。

### **3. M3：公式方向对了，但实现还没有完全对齐**

V1.0 已经把 CLeHe 的加权对数概率形式改正确了：

\[ \sum_i w_{i,t}\log p_\theta(y_t\mid q,d_i,y_{<t}) \]

这是重要修正。原论文确实使用低熵文档分布的加权对数概率，并与模型无上下文的高熵中间层分布进行对比。

ACL Anthology



但仍有三点：

**第一，Reliability-Weighted CLeHe 是你们提出的扩展，不是 CLeHe 原版。**

建议权重用更清晰的形式：

\[ w_{i,t}= \operatorname{softmax}_i \left( \log(\tilde R_i+\epsilon)-\frac{H_{i,t}}{\tau} \right) \]

这也修复了伪代码里先计算 \(R_i e^{-H_i/\tau}\)、再直接对该数值 Softmax 的不一致。

**第二，高熵参考层需要逐步选择。**

CLeHe 原文是在每个生成步，从候选的最后几层中选择熵最高的层：

\[ l_t^*=\arg\max_{l\in\mathcal L}H(p_\theta^l) \]

并不是简单地固定一个离线选出的早期层。V1.0 的 `forward_early_layer_dist` 需要按原始定义调整。

ACL Anthology



**第三，8GB 的串行成本必须重点关注。**

如果最终证据有 5 篇，每个生成 Token 都要计算 5 个文档条件分布，串行计算意味着每一步约 5 次文档条件前向，再加无上下文参考分布计算。它不是普通 RAG 的单次前向。

串行能够降低并行计算的显存压力，但会增加延迟。原 CLeHe 采用 document-parallel ensemble，不能因为把它改成串行就默认获得相同的运行效率。

ACL Anthology+1



另外：

-   `SYNCHECK` 需要实际的解码动态特征输入分类器，伪代码不能只写一个 `eval(current_sentence, D*)` 就视为实现完成。
-   `FOD` 是带 Beam Search 的忠实度导向解码，不只是句子失败后做一次普通重采样。
-   SynCheck 分类器需要轻量级监督训练，因此整个系统不能宣称完全不存在训练或标定。

最后，解码前的：

\[ \max_i R(d_i\mid q)<\tau_{\mathrm{abstain}} \]

也不能保证“100% 阻断幻觉”。只要存在一篇高分但错误的文档，就可能通过门控。需要把阈值与证据覆盖、冲突、答案正确率及 Risk-Coverage 一起校准。

### **4. 8GB：可作为目标，不可作为既定结论**

V1.0 给出的 6.5GB 是理论估算，不是实测。

FINAL_METHODOLOGY_PROTOTYPE.md



特别要注意：M1 的候选文档逐个计算 AU/EU，M2 可能计算多文档分布差异，M3 又需要多分支解码。这些操作的总时间成本和显存峰值不是简单相加几个组件就能准确估计的。

因此必须至少记录：

-   `torch.cuda.max_memory_allocated()`；
-   `torch.cuda.max_memory_reserved()`；
-   NVML 进程显存峰值；
-   各模块的端到端延迟；
-   单题模型前向次数；
-   输出长度不同情况下的延迟和峰值显存。

## **四、接下来最合理的研发顺序**

1.  **先完成 Baseline**

    BM25 + Dense Retrieval + Qwen2.5-7B，固定数据切片和实验环境。

2.  **单独验证 Self-FV**

    在 RAG 中控制证据歧义、标签噪声和 OOD，判断 AU/EU 分解是否真的能预测检索扩展需求。

3.  **优先重构 M2**

    独立实现证据可靠性评分、集合选择、冗余/冲突检测，再把 MST 作为组织工具。先证明它比普通 Top-K 更好。

4.  **最后接入 M3**

    分别测试 CLeHe 扩展和 SynCheck/FOD，避免混合所有机制后无法归因。

我的核心判断是：**U-GraphRAG 的研究方向值得继续，但 M2 才是决定这项研究能否形成独立方法贡献的关键。** 不要让一个图论算法的名字替代真正的证据集合优化问题。

下一步最有价值的是先把 M2 改写成一套完整的数学目标、可执行算法和消融矩阵，再更新为 V1.1 方法学文档。
